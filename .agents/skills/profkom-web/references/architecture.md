# Architecture and domain invariants

Use the current source/tests when a recorded detail disagrees. This repository is the live project; sibling export/archive copies are out of scope.

## Runtime and ownership

React/Vite -> nginx -> same-origin `/api` -> FastAPI -> SQLite and contextual S3 I/O. FastAPI creates one `/api` router in main.py; domain modules register their routes on it. OpenAPI remains `/openapi.json`.

- database.py owns legacy/core ORM, additive import-time schema upgrades, conversions, synchronization and Database.atomic. domain_models.py registers normalized extension tables on the same Base before create_all.
- models.py contains internal dataclasses; main.py and domain_contract.py define HTTP schemas. New domain services may return validated dictionaries rather than legacy dataclasses.
- access.py holds the release 1 access policy: `POLICY` maps each action to the relations that allow it (a rule may narrow by season state), `relations()` derives the actor's relations to a block, event, subevent or material, and `allowed()` backs both server checks and `capabilities`. Add or change a rule there, not at a call site; 403 messages stay at the call sites. registration, membership, participation, season_summaries, season_corrections, report_access, materials, directory, accounts and workspace own their corresponding workflows.
- auth.py owns passwords, JWT/session versions, refresh rotation and the central approval guard. vk_auth.py verifies provider data and explicit external identities; it never downloads a VK photo.
- file_access.py owns contextual uploads, actual-object verification and current ACL. Uploads target private/file_id staging; complete verifies a bounded GET snapshot and conditionally creates sealed/file_id with IfNoneMatch=*. Completed downloads/avatars use only sealed keys. Before cutover, batch-seal old completed IDs with scripts/seal_completed_files.py while the old API is stopped; its default dry-run is read-only and does not import settings or call storage. Lazy sealing on first read remains a compatibility fallback without a DB schema change; retention queues both keys. Provider support for conditional server-side PutObject is a deployment check. legacy_files.py resolves saved configured-bucket references at read time.

## Authorization and identity

All working content requires an active approved account, including blocks, legacy guides, files and contacts. Public auth operations do not expose content. Pending/rejected users have their own registration/session workflow. Backend checks remain authoritative even when UI buttons are hidden.

Chair/deputies come from explicit leadership/role assignments; the deputies share the chair's rights except opening and closing seasons and leadership changes, and only they change a closed season. Block master, per-principal deputies, event/subevent leaders and organizers grant scoped rights; event leaders and deputies also lead their subevents. The master of the explicitly configured is_hr block has global HR/KKR rights. Its actual deputy can read all block applications and decide the HR stage, without global KKR, analytics or public task-edit grants. Material editors are assigned per material by the chair and deputies; a block guide is also edited by the block's master and deputy. PGAS is edited by the chair, deputies and pgas_admin. A user who cannot read a task gets 404 on its PATCH.

Never infer rights from FIO, kkr_name, legacy admin/super_user flags or events_roles. A saved trusted master_user_id or explicit operator-ID mapping is different from matching a display name. VK subject links are explicit; provider email or FIO cannot authenticate an existing local account. Password change, archive and logout-all revoke existing access/refresh sessions. Role changes are checked from current DB state on every request. Session access_revision also fingerprints ordinary block membership and subevent organizer rosters; the frontend removes private cache and remounts its observers when access changes. Session is checked on focus and every 60 seconds.

## Transactions, IDs and history

Every HTTP command uses one unit of work. The async HTTP dependency uses Database.async_atomic: writers await a local lock and SQLite BEGIN/commit/rollback run outside the event loop; synchronous services/scripts retain Database.atomic. Keep ContextVar propagation and rollback intact. Nested Database operations flush instead of independently committing. SQLite BEGIN IMMEDIATE serializes writes; revisions and unique indexes cover competing planned/current seasons, roles, contributions, final reports, summaries and memberships. Invalid bulk commands roll back completely. Do not bypass synchronization helpers with ad-hoc roster writes.

Block IDs are stable UUIDs mapped to legacy names in BlockMeta; internal legacy task/role/source storage still uses names in some tables, so use membership boundary conversion helpers. Renaming must preserve IDs and update coupled internal names. Master/deputy service roles are independent from ordinary membership.

Registration applications have a bounded resubmission history. Block requests have separate HR/block stages and server-owned 72-hour clocks. Membership and active/approved participation intervals drive category promotion; scores do not imply tenure. Unknown imported dates remain unknown. A separate observed-state migration records participation from its observation timestamp onward, enabling future tenure without backdating a legacy join.

Closed summary versions freeze participants, categories, master recipients, bonus bases and the previous-summary version. Corrections are atomic and versioned. Report publication/version history is independent of KKR. Closed report editors are saved actual leaders/deputies; removed authors get no fallback right. Current corresponding-series leadership grants published historical read, not draft/edit or past tracker access.

Season analytics is a read-only global summary/KKR projection. Distinct privately accepted evaluated tasks and accepted-assignment hours remain separate from all-contribution KKR, including negatives/merits/bonuses. Weeks use actual work dates in Moscow time, with unknown dates separately unallocated; this is no reconstructed historical balance. Closed seasons use the latest approved immutable snapshot. New versions embed internal analytics facts (stripped from HTTP summary DTOs); older versions are never backfilled and retain null task/hour/date gaps. HR deputy's tracker read does not grant analytics. See backend/docs/SEASON_ANALYTICS.md.

Materials separate shared draft and published content. Legacy guide IDs/texts and PGAS references survive explicit adapters. Current contact writes are owner-only; former cards are independent records edited by the chair, the deputies and the HR master. Avatars use local presets or a completed owned file. Draft attachments remain private until publication.

Archive preserves inactive assignments, closes intervals and revokes sessions. Restore resolves occupied master positions and never resurrects global roles from a previous chair term. After three calendar years, retention replaces account identity with an anonymous accounting participant, preserving agreed former cards and numeric history. Avatar deletion uses a retry queue after the DB transaction. Internal disabled tombstones preserve historical non-null FKs; do not physically delete an account through HTTP.

## Migration and deployment

Startup migrations are idempotent, but can reject conflicting legacy rows. Rehearse on a backed-up copy using scripts/migrate_v13.py; dry-run must not import the app or write schema. Privileged/VK/HR mappings use verified IDs; never guess historical dates. See backend/docs/MIGRATION_V13.md and ACCOUNT_RETENTION.md.

The backend Docker image runs Python 3.12 in production mode and excludes secret files. Compose injects backend/.env at runtime. Production requires a unique JWT secret; empty-install chair bootstrap uses explicit configured credentials and never resets/elevates an existing account by email. Private bucket ACL/CORS, provider credentials, actual image build and deployment need environment-specific verification.

The personal home reads `/participation`, a compact projection of the actor's actual block memberships and team assignments in non-closed seasons. Global chair/HR rights do not expand this projection; `/dashboard` remains the separate compatible operational projection. Meeting overviews distinguish the event's main announcement and readable child-team announcements; cached meeting data and editors require current owner access.

Frontend uses a React Router data router. UnsavedChangesProvider blocks route/POP exits and beforeunload; local modal/context exits use scoped guards so discarding one editor does not erase unrelated drafts. ActionForm registers fields plus explicit external Markdown/attachment state and upload activity. Navigation saving uses normal validation/revision checks, never automatically publishes or runs destructive commands. Opt-in useForm guards protect standalone PGAS/guide modals; auth forms are excluded. Successful save clears the leave-warning baseline while keeping versioned editor input/revision protected against foreign refetch until explicit replacement.

Frontend uses shared CSS Modules/tokens, TanStack Query, Axios single-flight refresh and focused API modules. API 1.3 types are in utils/api/contract.ts; legacy adapters remain in types.ts. Development demo mode is separate from real-local API integration and disabled in production. Old unscoped upload is deprecated; use filesApi intent/upload/complete.

Versioned ActionForm holds the editing baseline across refetch, including a lossless revisionKey vector for bulk/closed commands. Own sibling commands may advance only a matching from->to baseline. Markdown and attachment replacement must reset external state together with Formik. Closed summary correction returns applied_revisions from its write transaction; never silently accept a newer GET revision as the command acknowledgement.

The tracker public workflow is freely editable by every current task reader and is independent of private Assignment accounting. TaskTracker stores public status/public assignment revision snapshots and separate TaskInputs assessment_revision; Assignment inputs/workflow revisions protect private outcomes. Public statuses/results/roster never create a completion date or credit. Authorized evaluation may use an actual recorded submission timestamp; manual date overrides keep original rights. Accounting unresolved/season-close use private outcomes; independent queue tasks have no invented KKR source. TaskQueue may be independent (scope null; Task scope kind queue), scoped, public or private. Active approved users create their own queues; readers create unassigned/self-assigned tasks, with other-person/private-input initialization restricted to original roles. Only chair/chair-deputy/HR-master/HR-deputy read all queues; HR-deputy gains no unrelated reports/KKR rights. TaskRoster persists assignees/watchers independently of ledger rows, uses task revisions, preserves credit on remove/rejoin, and drives notifications. Safe history resolves current UserRefs without cached personal names and excludes private notes/inputs/audit. Pre-create file drafts are uploader-only and transactionally bound on creation; byte ACL repeats after queue revocation. See backend/docs/TRACKER_WORKFLOW.md.

Shared interactive chips use composition: ChipFace/ChipAvatar own the visual identity; InteractiveChip selects native link, action or display semantics and keeps an optional trailing action as a sibling control. HoverCard is a lazy, read-only preview; interactive editing belongs in AnchoredPopover with its own UnsavedChangesScope. UserChip, BlockChip/TeamChip and AccountingChip own authorized data and domain routes. EntityPicker keeps ID selection/keyboard behavior and uses display-only ChipFace, without profile queries. Permission failures must hide stale preview data. SectionHomeLink unifies the section stamp and preserves Router navigation guards.

Block avatars are completed owned contextual files (`owner_kind=block`, stable block ID, purpose avatar), bound explicitly under edit_block with the block revision. DTOs expose only the same-origin protected content path. Replacement/clear atomically retires the old FileRecord and schedules both object keys for cleanup; no user-avatar owner shortcut or public bucket URL is used. Validation reuses the existing bounded file signature/metadata and sealed snapshot policy, not a full image decoder. See backend/docs/BLOCK_AVATARS.md.

POST /api/tasks/{id}/take atomically self-assigns a current reader, removes their watcher row and sets the public status to in_progress in one task revision. Repeated satisfied commands are idempotent, stale revisions roll back, and existing private assessment/outcome/input revisions stay intact. A direct public status change never self-assigns. AccountingChip opens the selected assignment assessment inside the task through assignment_id; it does not create a separate assessment route.

Tracker planning stores public task_type (task/milestone/epic), priority and optional starts_at independently from accounting. A milestone is a deadline point with no planned start. Goals are not part of the API. Canonical task_links store related/blocks and ordinary-task membership in one epic/multiple milestones; inverse relations are projected, and epic/milestone grouping is independent of parent decomposition. All endpoints must be readable, links stay within one season, dependency cycles and incompatible type/season changes are rejected atomically. Both public task revisions/history advance for links; hidden targets are masked at read time. Dependencies warn and never constrain the freely editable public status. Checklist items have stable IDs/order; identity-only changes also advance public revision. Personal favorites change neither public revision/history nor accounting. Calendar/Gantt exhaust all page cursors for an exact half-open Moscow planning window; a 403/404 from either active query suppresses cached rows even if another query failed transiently. See backend/docs/TRACKER_STAGE2.md.

Task classification is a per-reader public action, including scoped closed-season tasks: capabilities change_task_type/change_task_priority authorize PATCH task_type/priority. Explicit starts_at (including null) still requires the existing can_edit_public/edit_task_metadata permission; full checklist text/order/identity replacement still requires can_edit_description/edit_task_checklist. Mixed patches validate every supplied field atomically: adding an allowed type/priority field never grants a protected edit. Type-only milestone selection implicitly clears the planned start after field permission checks, records task_type and starts_at diffs together in one public revision, and retains epic/milestone membership constraints (task_type_conflict). It never changes private dates, inputs, credit or accounting. This refinement adds no SQLite schema change.

POST /api/tasks/{id}/checklist/{item_id}/toggle accepts expected_revision and a strict boolean checked and returns the full readable Task. Every current reader has toggle_task_checklist, including closed seasons. The command checks the current task revision before the item ID, rejects foreign/missing IDs with 404, changes only the stored checked flag, and emits the ordered checklist diff with the actual actor in one public task revision. Repeating the same checked value at the current revision is a no-op with no new history/timestamp/revision; a stale revision still returns 409. This command does not widen Markdown-description, checklist-text, order or private KKR permissions.

TaskClassificationMenu shares type/priority icons between list rows and parameter controls; task titles omit duplicate classification controls. Its portalled radio menu stops row navigation, submits only the selected field plus expected_revision, and registers successful matching own-revision changes without acknowledging foreign conflicts. The pending trigger remains focusable with aria-disabled/aria-busy while synchronous guards prevent duplicate activation; choosing an item preserves keyboard focus without stealing it from another control. Permission loss hides unavailable task data through normal authorized refetch/cache guards.

Queue ownership recovery runs in the identity/role/membership transaction, using final flushed state and current central ACL: actual block master for block queues, then actual HR master, then current chair. Independent/subevent queues skip the block tier; deputies and legacy names are not fallbacks. If no candidate is eligible, the historic owner remains marked unavailable. Transfer increments queue revision and appends audit atomically, grants no membership/KKR rights, and restore never reclaims a transferred queue. GET does not repair ownership. Startup reconciles once; database-first imports run normally, while a partially initialized access import defers recovery until the central policy is fully defined. Test populated legacy databases through main-first/database-first/access-first imports twice. See backend/docs/QUEUE_OWNERSHIP.md.

The actual master of the configured HR block has global public task.edit rights in non-closed seasons, including foreign/private independent queues; current central relations, not cached names or legacy admin flags, grant this permission. The HR deputy's global queue/task read does not imply global task editing. Existing closed-season edit rules and private assessment/report/analytics permissions remain unchanged. Description editing includes revision-protected Markdown checklist toggles and public history.

WorkspaceLayout shows one NotificationBell for an active approved session, outside the sidebar links. It shares the full paginated notifications query/read/read-all commands with the compatible /notifications page. Opening the popover does not mark items read; following a source commits read only after the unsaved-changes navigation guard accepts, with existing modified-click semantics. Counts exclude read items, display 99+ visually, and remain exact in the accessible label. Non-retainable permission errors hide cached notices/counts, and inactive/forced-password-change sessions neither render nor fetch the widget.

The Blocks page projects the whole organization as semantic nested lists: current leadership above block branches, with block leaders separated from ordinary members. It reads the existing leadership/workspaceBlocks/contacts queries; explicit deputy IDs are resolved from authorized UserRefs, including deputies without ordinary membership. Only name/avatar/profile links are rendered from contact data. A non-retainable error in any source hides the combined cached tree; unknown deputy IDs remain unavailable placeholders. Leadership.chair is nullable, matching the backend. Shared UserChip/BlockChip keep native links, previews and avatars.

Calendar entries identify their season with an explicit season-label InteractiveChip and calendar icon, linked to the season independently from the entry source. The full season title remains in the accessible name and title attribute when its visual label is truncated.

OrganizationTree keeps block expansion locally by stable block ID, collapsed initially. Search normalizes case and yo/e across block and participant names, automatically expands whole matching branches, and leaves the top leadership visible with a separate match count. Clearing search restores manual expansion; native toggle/all controls never replace the block navigation link. Hidden branches unmount their member/preview content while retaining aria-controls targets.

Material creation has its own /materials/new canvas behind the create action; existing materials open as readers and enter a scoped editor through a capability-gated pencil. Draft text is initialized/replaced only from canonical source_content. Description/original-link metadata and Markdown belong to the same guarded external form state/revision. Save draft, explicit publish, audience, editor roster and guarded soft deletion keep their existing individual rights and material revision tracking. Navigation saving never publishes or deletes; create itself stays explicit. Non-retainable query errors hide cached titles/private drafts and unmount the editor.

BlockMeta.hr_user_id is an explicit nullable block curator assignment, independent of the legacy block.hr display string and ordinary membership. Chair/deputies and the HR master assign or clear it through PUT /blocks/{id}/hr with the current block revision. It grants scoped block task/read/assignment, private KKR inputs/review and volunteer accounting, never guide editing, application approval, global analytics or leadership management. Existing private-queue grants, self-rating and closed-season restrictions still apply. Session access revisions and queue ownership recovery observe curator changes; removal does not remove memberships or accounting. Initial schema migration leaves every assignment empty; temporary test-site staffing uses the API separately, never an identity inferred from a name.

A current ordinary member, block master or its actual deputy cannot apply to join the same block (409 already_member). Historical roles do not block a later application; a curator without ordinary membership/leadership remains eligible to apply and cannot decide it. Creation of a completed-work merit no longer requires an extra reason field: the server records a default creation provenance if omitted. Corrections, including closed-season corrections, still require their explicit nonempty reason.


## Unified workspace extensions

Events/subevents keep optional dates and all-day metadata in event_workspace_metadata. A subevent's public announcement and roster are distinct from its working description and working ACL. HR is assigned explicitly to subevents only. Calendar/home derive authorized entries and overlapping date intervals in Moscow time; support tickets may have no season or deadline.

WEBSUPPORT is a dedicated service queue in an explicitly configured stable block. Its staff gate is checked before generic global-queue readership. An approved reporter reads only the linked own ticket, with ordinary public tracker actions; this grants neither whole-queue access nor private KKR or internal support notes. Anonymous intake is write-only. Feedback persists independently of task creation, uses idempotency and bounded fair retries, and private sanitized diagnostics expire after 90 days. Protected screenshots are fetched through the authenticated API client as blobs.

Profile edits and avatar drafts share one atomic save/revision/fingerprint. Awards retain issue/revoke snapshots; KKR templates retain the selected template and actual applied values in the accounting transaction. Notification preferences collect reference-only disabled delivery events. Future delivery must recheck current access; no provider sender is connected.

History projections separate public task changes from private assessment inputs. Hiding a foreign version requires proven leadership at the change timestamp and current object access; present leadership alone is insufficient. Block ScopeTenure.scope_block_id supplies stable provenance. Legacy label-only periods/audits never inherit authority from a reused current name. Redaction retains a tombstone and does not rewrite current accounting or approved numeric snapshots.

Materials retain legacy GuideORM IDs internally, but old /api/guides CRUD and dead editors are retired. Bookmarks resolve through /materials/legacy-guides/{id} with current material ACL. Trash has an explicit nullable deletion date and a calendar-year lifetime; unknown legacy dates never imply expiry. Metadata removal queues durable object deletion without calling S3, preserving shared references. Account cleanup similarly separates DB/queue apply from the explicit object-drain command.


BlockRequest.approvals is a read-only projection of saved approval transitions, with distinct HR/block stages, the actual actor UserRef when resolvable, nullable date and substitute flag. It never substitutes today's master for an unknown historical actor and never returns raw history/reasons. GET does not repair history or write the database. Current request listing/approval ACL remains authoritative.

Calendar day/week/month views and the workspace Today widget share CalendarViews/calendarLayout: half-open Moscow day windows, all-day strip, real interval lane packing and point markers for records without duration. Month links show a compact subset with a day drilldown; hover/focus details use the authorized CalendarItem projection without extra private participant reads. Calendar mode/date/filters live in the URL. PGAS periods are filters over a flat table; unknown legacy periods stay unknown, while the small period editor freezes the opened revision and requires an explicit reread after a conflict.

Own notification preferences live at /profile/settings, KKR template management at /seasons/templates under its existing scoped rights. Profile achievements use one accessible icon button per grant with guarded detail popovers; grant history and management stay collapsed by default.

AnchoredPopover focusRoot is opt-in for long read-only achievement details: focus the dialog root without scrolling the header away. Other consumers retain their existing initialFocusRef/default input focus behavior and visible control focus styles.

Full day/week calendar bodies use natural page height and never auto-scroll the page on mount. Only compact Today keeps a bounded vertical scroller and initial hour positioning; mobile week can still scroll horizontally within its frame. Feedback is launched solely through the global fixed button; there is no separate home widget/context consumer.

Read-heavy workspace endpoints use `task_reads.TaskIndex` for public selection/facets and the central batch queue ACL before detailed DTOs. Calendar builds no full task DTO, Home reuses its personal selection and hydrates at most ten cards; missing legacy metadata cannot repair/rebind a hidden task. Queue catalogues omit editor-only assignment candidates, fetched through the detailed queue GET. Read-only database units have request-local detached-value/identity memoization, permanently disabled by any write/dirty state/flush/transaction boundary; no TTL or cross-request permission cache. Core/driver writes also expire clean held ORM attributes. See `backend/docs/READ_PROJECTIONS.md` and the focused read-projection/context regressions.

Selected task pages prepare detailed relations in bounded batches while retaining the original converters, capability checks and legacy ordering. Read scopes may reuse immutable ORM identity tuples, absent PK results, task/queue ACL booleans and scalar role/block mappings; mutable DTOs are never shared. Multi-row rosters and joint/tied legacy submissions retain their original task-local ordering queries. Notification task-target ACL is batched only after the existing payload dispatch precedence; unavailable targets remain redacted. Personal participation reads compact ORM hierarchy and central relations instead of full leadership cards.

Frontend reader/editor routes import dedicated modules through the existing React.lazy boundaries; result submission and editor-only modules load on explicit action. Session approval/password/access checks remain authoritative, while personal-profile loading no longer blocks independent workspace reads. Own profile routes still wait for initial profile data. Inactive cache eviction on an access revision includes disabled observers. Closed filter catalogues and unused list pages do not fetch; planning retains exhaustive cursor traversal and active-query refusal guards. Search coalesces read requests and forwards cancellation through pagination. See `frontend/docs/READ_PATHS.md` for the loading and measurement contract.

The season participant panel mounts only one active decision ActionForm; closed rows have no Formik subscriptions. Switching rows, closing the editor and changing local participant filters use its UnsavedChangesScope with save/discard/stay. Sorting keeps stable participant identity. Saving retains summary-version conflict checks and ordinary capabilities; filtering or opening a row never writes a decision. See the repeated-row and draft-preservation cases in `season-freeze.test.tsx`.

The contact directory reads participant categories through bounded `/participants/categories?user_ids=...` batches (up to 200 unique positive IDs), with the same category/revision/capabilities as the single-target endpoint. Unavailable targets are omitted, absent category revision reads as 1 without repair, and reasons/history/KKR are excluded. The management panel keeps a fresh single-target query and its revision-protected command. Both query shapes share the participantCategory invalidation prefix. Event leadership display is independent of route/editor modules; event editors load through local Suspense boundaries. Static-only gzip/cache policy is separate from API/private-file serving; test Basic Auth is retained on every static location, and deployed nginx changes require their own guarded validation/rollback.
