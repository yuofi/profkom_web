# Блоки: настройки, удаление и сезон задач

[Frontend](README.md) · [Решение владельца](../../docs/decisions/2026-11-10-block-lifecycle.md)

Кнопка «Создать блок» в существующем каталоге опирается на session capability
`create_block`. «Настройки блока» на карточке объединяют переименование
(`rename_block`), прежний редактор аватара (`edit_block`) и запрос удаления
(`start_block_deletion`). Мастер сохраняет прежнее право на фотографию и описание;
новые права не выводятся из названия роли на клиенте.

Удаление проходит через подтверждаемые сервером состояния. Инициатор даёт первое
подтверждение; второе даёт другой действующий председатель или заместитель.
Сервисный аккаунт не считается человеком для этого решения. После второго
подтверждения сервер назначает 72 часа ожидания. Карточка показывает авторов и
время обоих решений, срок в Москве, оставшееся время и отмену по capability
`cancel_block_deletion`. До срока блок продолжает работать. По окончании он
скрывается из общего каталога, а новые задачи в его очередях запрещены; исторические
задачи, гайды и ККР остаются доступны по прежним правилам чтения.

Все команды используют **ревизию блока**, а подтверждение и отмена дополнительно
передают `request_id`. После записи обновляется `['workspaceBlocks', block_id]`
и существующий workspace cache. Только карточка с активным запросом опрашивается
раз в 30 секунд, только в видимой вкладке; отмена или завершение прекращают опрос.
Локальный таймер никогда не удаляет блок и не выдаёт права. Уведомления руководству
сразу, спустя 24/48 часов и по завершении создаёт backend.

В существующей форме задачи блока сезон можно оставить «Укажу позже», даже если
нет открытого сезона. Явный пустой выбор сохраняется при повторном чтении данных
и передаётся как `season_id: null`. Для задач председателя, мероприятия и
подмероприятия действуют прежние ограничения. Отсутствующий сезон отмечается
красным «Укажите сезон до закрытия». Начальное назначение разрешает task capability
`assign_season`; доступны запланированные, открытые и подводящие итоги сезоны.
Даты и совместимость связей окончательно проверяет backend.

При закрытии задачи без сезона общий `TaskStatusMenu` открывает выбор. Сохранение
посылает **один** `POST /tasks/{id}/status` с `status: closed`, `season_id` и
`expected_revision`: промежуточного PATCH нет. Отмена ничего не записывает.
Существующий `onClosed` затем открывает ККР. Если сезон уже назначен, его перенос
остаётся в прежнем интерфейсе исправления сезона. Календарь принимает дедлайны
без сезона, показывает «не указан» и не создаёт фиктивную ссылку.

Проверки: `block-lifecycle.test.tsx`, `block-task-season.test.tsx`, API wire-contract
`utils/api/tests/block-lifecycle.test.ts`, прежние `task-accounting` и
`calendar-season-chip`. Реальный HTTP и браузерные сценарии проверяются отдельными
локальными integration/e2e наборами на синтетических данных.
