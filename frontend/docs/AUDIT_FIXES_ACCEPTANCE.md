## Журнал по пунктам

- A01: старые `/admin/users`, `/admin/blocks`, `/admin/events` перенаправлены в текущие экраны; три неиспользуемые панели с PATCH привилегий/JSON ролей/старым составом удалены. Управление гайдами сохранено. Три DOM-проверки прямых старых URL проходят с нормализованными DTO без старых мутаций; прежняя регрессия совместимости проходит.
- A02: сохранённый useForm использует общий normalizeApiError, показывает строковое сообщение и ошибки полей (включая FastAPI loc/msg), не сбрасывает ввод. Четыре DOM-сценария: структурированные 403/409/422 и ошибка Axios-адаптера. Все проходят; вместе с A01 — 7 тестов.
- A03: вход/регистрация/VK используют общий session-first переход и удаляют данные прежнего аккаунта; профиль загружает provider только для active/approved. Ручное обновление pending больше не вызывает профиль. Единый выход из профиля/карточки/состояния регистрации вызывает logout, очищает кеш и токен; ошибка сети остаётся видимой с повторной попыткой. Пароль/VK проверены для active/pending/rejected, ошибки VK и logout — отдельными DOM-сценариями; 12 проверок auth/provider/client проходят. Реальные VK/refresh-cookie остаются интеграционной проверкой.
- A04: добавлены scoped-входы блока/мероприятия/подмероприятия и раздел выбора сезона; типы/области создания определяются объектными capabilities. Для блока/председателя доступны open/summarizing, для мероприятия — его собственный незакрытый сезон, включая planned. Главорг больше не зависит от глобального volunteer-флага. DOM-сценарии проходят от карточки до сохранения двух типов записи без запросов сводной/расчёта; читатель без прав форму не получает. Вместе с прежними тестами форм — 18 проверок. TypeScript проходит.
- A08: кандидаты руководства отбираются по in_profcom; перед отправкой повторно проверяется текущий справочник, загрузка/ошибка справочника имеют свои состояния. DOM-проверка исключает pending, сохраняет действующего кандидата вне блоков, показывает серверный 422 и блокирует устаревший выбор. Файл первой группы: 11 тестов проходят; общий ESLint проходит.
- Дополнительная проверка A02 на настоящем ProfileEditPage обнаружила fire-and-forget mutate, обходивший обработчик useForm. Заменён на mutateAsync, ошибки контактов/пароля передаются нормализатору; ошибка поля видна, ввод сохранён, обновление профиля не затирает грязный черновик. Старый вход `/admin` из профиля исправлен на существующий URL и capability. DOM-регрессия профиля проходит; файл первой группы — 12 тестов. До этой дополнительной правки общие 120 тестов, ESLint и production build проходили; TypeScript/ESLint повторены после неё.
- A05: формы мероприятия/подмероприятия, блока, регистрации, созвона, сезона, решений, категории и руководства привязаны к ID, а не версии. Версия отправки удерживается до явного принятия обновлённых данных; сравнение и замена ввода доступны отдельно. В отсутствовавшие места добавлено обновление после конфликта. QueryState сохраняет редактор при временной сетевой/5xx ошибке, но убирает закрытые данные при 401/403/404. Восемь DOM-сценариев проверяют шесть семейств через 409 → чтение → сохранность → подтверждение → успешный повтор, фоновую смену версии и сохранность при сетевой ошибке/отзыв доступа. Вместе с auth/прежней приёмкой — 21 проверка; lint и TypeScript проходят.
