# Оформленные вставки в гайдах

В гайдах блоков редактор может включить формат `markdown-embeds-v1` через
меню «Вставить». Нужны действующие права `edit_material` и доступная серверная
возможность `edit_html_material`. Новый материал сначала сохраняют в черновик:
после этого у загружаемых изображений есть конкретный владелец.

## Работа редактора

Меню предлагает плашку, кнопку-ссылку, таблицу, изображение, шаги, колонки,
раскрывающийся ответ и HTML-композицию. Обычные настройки заполняются полями:
заголовок и текст, цветовая тема, мягкий градиент, компактные отступы,
выравнивание. Кнопка ведёт на HTTPS-сайт, относительный маршрут, другой
опубликованный гайд или выбранный заголовок. Внешняя ссылка открывает новую
вкладку с понятным обозначением.

У таблицы есть название, заголовки и редактируемые ячейки; на телефоне
прокручивается таблица, а не вся страница. Изображение загружается через
контекстный API материала; доступны описание, подпись и размер.
Картинки имеют заданные размеры, асинхронное декодирование и отложенную
загрузку после первого изображения. Цветные карточки используют палитру
сайта; сетки становятся одноколоночными и внутри узкого предпросмотра.

Вставка добавляется в каретку существующего Markdown-редактора и входит
в его undo/redo. Исходник остаётся доступен, HTML можно менять вручную.
После ручного изменения HTML поля не перезаписывают композицию.
Включение формата явно подтверждается: случайные старые кодовые блоки
`profkom-html` нельзя незаметно превратить в оформление.

Предпросмотр запускает серверную проверку только когда открыт, после
350 мс без ввода. Устаревший ответ не заменяет новый текст; запрос отменяется
при закрытии. Можно выбрать ширину 390, 768 или 1280 px. Ошибки показываются
с номером строки, не скрывая исходник. Сохранение черновика и публикация
остаются разными действиями; перед публикацией доступно сравнение с текущей
версией. Некорректный сохранённый черновик не публикуется.

## Чтение и совместимость

`MaterialContent` лениво подключает `GuideEmbeds` только для расширенного
формата. Общий `MarkdownContent` по-прежнему использует `skipHtml`; задачи,
комментарии, отчёты и обычные материалы не получают HTML-режим. Не загружается
новый HTML-парсер в браузер читателя. Существующий Markdown-парсер используется
для распознавания fence, а серверное дерево рисуют фиксированные React-узлы.

`guideEmbedPolicy.ts` повторно проверяет теги, URL, свойства и пределы дерева.
Неизвестная версия или несовпавший исходник получают безопасное текстовое
представление. Нет `dangerouslySetInnerHTML`, произвольных CSS/JS, iframe или
внешних изображений в HTML-вставках. Стили назначаются только через конечную
карту классов CSS Modules.

Якоря именуются внутри материала: обычные заголовки — `section-N`, заголовки
вставки — `<embed-id>-heading-N`, DOM получает префикс конкретного материала.
Содержание собирается из окончательно отрисованных заголовков, включая
лениво загруженные вставки. Перестановка обычных заголовков меняет их номера:
после неё следует проверить смысл кнопок-переходов. Несуществующий якорь
не проходит серверную проверку.

Ссылки `file:<id>` в расширенном материале (в том числе в Markdown и галерее)
преобразуются только в защищённый адрес `/api/files/<id>/content`, не в
публичный S3 URL. Проверку доступа на каждый запрос сохраняет backend.

## Журнал: целая страница из редактируемых блоков

Формат `journal-v1` дополняет прежние гайды. У него один заголовок из поля
«Название материала», вступление, цветная или загруженная обложка, компактное
оглавление и пронумерованные разделы. На широком экране название раздела
стоит слева от его содержания, на телефоне — сверху. Цвета используют темы
сайта; ширина предпросмотра тоже переключает композицию.

В сохранённом гайде кнопка «Перейти к Журналу» открывает явное подтверждение.
Markdown разбивается по заголовкам второго уровня CommonMark вне блоков кода;
другие уровни сохраняются в текстовых блоках. Литералы вроде `C#` не обрезаются.
Если ссылки или изображения используют общие определения `[name]: адрес`,
исходник переносится целиком, чтобы не разорвать ссылки и старые якоря. При наличии
инертных примеров `profkom-html` используется текстовый блок: пример не должен
внезапно стать действующей вставкой. Такой блок сохраняет лимит 8192 символа;
превышение остаётся исправляемым черновиком и не публикуется. Старый
`markdown-embeds-v1` переносится целиком в блок прежних вставок; HTML не
пересобирается по частично распознанным полям. До сохранения можно вернуть
точный исходный текст. После сохранения обратного автоматического преобразования
нет — редактор объясняет это до перехода.

Структура слева выбирает один раздел или блок для редактирования. Доступны:

| Блок | Для чего |
| --- | --- |
| Текст | Короткое объяснение, Markdown, таблица, ссылка |
| Плашка | Совет, предупреждение, важное условие |
| Сравнение | Неудачный и хороший пример |
| Коротко о главном | 2–4 факта с подписями |
| Шаги | 2–6 действий с указанием роли |
| Изображение | Файл гайда, подпись, увеличение, показ по нажатию |
| Подробности | Раскрывающийся ответ |
| Варианты примера | 2–4 варианта, переключаемых читателем |
| Прежние HTML-вставки | Сохранённая композиция предыдущего формата |

Блоки и разделы можно переставлять, дублировать и удалять; последние изменения
отменяются и повторяются. ID раздела сохраняется при переименовании и перемещении:
ссылка `#create` остаётся привязана к нему. Копия получает новый ID. Тексты
обычных блоков поддерживают Markdown; произвольный HTML в них не исполняется.
Ссылки задают явно: `[текст](https://example.org)`. Незаписанные таким образом
адреса и email остаются текстом. Прежний fenced-блок `chip` показывается кодом,
чтобы его фотография не создавала скрытый запрос к внешнему сайту.

Предпросмотр показывает весь гайд без открытых форм. Проверка начинается после
350 мс покоя, отменяется при уходе и не сохраняет материал. Сохранение создаёт
черновик, отдельная публикация меняет читательскую версию. Ошибочный JSON
остаётся доступен как исходник, а не заменяется пустым документом. Повторные ключи
JSON, включая одинаковые ключи с Unicode-экранированием, также запрещают переход
к полям: редактор не отбрасывает первое значение через `JSON.parse`.

`JournalGuide` загружается лениво. `journalPolicy` проверяет конечную схему и
совпадение документа с исходником перед рендерингом. Оглавление содержит только
явные разделы, без поиска по DOM. Переключение примера не обращается к API;
скрытые панели и закрытые изображения не монтируются до открытия. Для печати
раскрываются все варианты. Закрытые иллюстрации не нужны для первого отображения
страницы. Изображения используют контекстные защищённые адреса файлов, размеры
и асинхронное декодирование.

Проверки журнала: `journal-guide.test.tsx`, `journal-editor-model.test.ts`,
`journal-editor.test.tsx`, `journal-guides.integration.test.tsx`,
`e2e/journal-guides.spec.ts`. HTTP-набор использует одноразовую SQLite-базу;
браузерный — production-сборку, настоящий локальный компилятор и синтетический
API на размерах компьютера и телефона. Пример композиции:
`src/test/fixtures/journal-tracker.json`.
