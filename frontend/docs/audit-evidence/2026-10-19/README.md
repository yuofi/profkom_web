# Диагностики до исправления LOC-01–03

Эти файлы — архив воспроизведений нежелательного поведения на `c52451d`.
Они намеренно проверяют существование дефекта. Зелёный результат не является
продуктовой приёмкой. После исправления нужны постоянные тесты с обратным
ожиданием из [плана](../../WHOLE_SITE_AUDIT_2026-10-19.md).

Расширение `.txt` исключает случайный запуск обычными Vitest/pytest.

Для повторения из корня репозитория скопировать frontend-файл в
`frontend/src/pages/Workspace/whole-site-audit.tmp.test.tsx`, backend-файл — в
`backend/tests/test_whole_site_audit_tmp.py`. Перед копированием убедиться,
что этих временных файлов нет, чтобы не перезаписать чужую работу.
Относительные импорты рассчитаны именно на эти места.

Frontend: из `frontend/` запустить установленный локально Vitest:
`node node_modules/vitest/vitest.mjs run src/pages/Workspace/whole-site-audit.tmp.test.tsx`.
Его конфигурация задаёт тестовое окружение, transport полностью подменён.

Backend: из `backend/` запустить Python 3.12 с зависимостями проекта:
`python -m pytest tests/test_whole_site_audit_tmp.py -q -s`.
Сначала автоматически загружается `tests/conftest.py`: он устанавливает
синтетическую DATABASE_PATH до импортов приложения, очищает временную БД и
подменяет внешние сервисы. Защитный assert архивного файла не разрешает запуск
без такой БД. Прямой запуск файла/импорт вне этого процесса не нужен.

В backend-диагностике `live_storage.install` добавляет тестовый ASGI-маршрут
только в текущий процесс. Поэтому запускать её отдельной указанной командой,
не вместе с инвентарём production-маршрутов. Никакие порты не открываются.
При последующих запусках постоянного набора используется обычное приложение.

После проверки удалить только эти два созданных временных файла; архив и
постоянные исходники оставить. При выполнении аудита временные файлы уже удалены.
Логи исходного запуска и manifest:
`/private/tmp/profkom-whole-site-audit-20261019-Z9XRgk/`.
