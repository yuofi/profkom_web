# Независимая проверка frontend

Новые модули `src/utils/api/*.api.ts` реализуют контракт 1.3. Старые auth/guides/pgas-клиенты сохранены для совместимости. `contract.ts` разделяет публичные задачи, исходные поля и расчёт. `request.ts` нормализует ошибки, а новые списки проверяет на `{items,next_cursor}`: массив от несовместимого backend не превращается в успешный ответ незаметно.

## Запуск

`npm ci`, `npm run lint`, `npm run build`, `npm test -- --run`.

Независимый набор не обращается к живому backend. `npm run test:integration` запускается отдельно против специально подготовленной локальной временной базы; он регистрирует синтетические аккаунты. Общие или production данные для этого не использовать.

Моки находятся в `src/mocks/`. `startDevelopmentMocks` подключается перед первым запросом приложения только при `import.meta.env.DEV` и включённом `VITE_DEMO_MODE`. Production не использует этот путь. Во время реализации нового каркаса точка запуска подключается в `main.tsx`.

Профили: organizer, leader, hr, hr-deputy, chair, chair-deputy, editor, pending, rejected, archived, multi. Выбор в DEV задаётся `VITE_DEMO_ROLE` или ключом sessionStorage `profkom-demo-role`. Рабочие данные хранятся только в памяти транспорта и сбрасываются при перезагрузке; это не серверное сохранение.

Тесты вызывают `installMockTransport(role, {delay: 0, scenario})` и обязательно `restore()` после проверки. Сценарии: normal, empty, error, conflict. Необработанный маршрут возвращает 501, без выхода в сеть. Прямой upload использует отдельный mock Axios, complete до бинарной загрузки возвращает конфликт.

## Границы доказательств

Моки проверяют клиентские формы, команды, revisions, обработку ошибок и представления ролей. Они не доказывают серверные ACL, транзакции, идемпотентность, реальный S3, формулу ККР или сохранение данных. Расчётные цифры в фикстурах заранее заданы; формулы в mock transport нет.

## Кеш

Обычные изменения инвалидируют затронутые query keys; общие изменения области/сезона используют `invalidateWorkspace`. Смена пользователя или отзыв полномочий используют `clearPrivateCache`: отмена запросов, удаление закрытого кеша, повторное чтение сессии. Восстановление доступа не определяется совпадением ФИО или прежним legacy admin-флагом.
