Дополнительно найденные и исправленные дефекты:

- Formik превращал изменённое поле number в число, хотя общая схема ожидает строку. Отправка введённых часов останавливалась до API. Теперь хранится строковый ввод; числовой payload подтверждён UI-тестами и браузером с 2,5 часа.
- Смена revision пересоздавала редакторы и удаляла несохранённый ввод после обновления конфликтующих данных. Ключи привязаны к ID объектов. Два отдельных QueryClient проходят конфликт отчёта: оба набирают текст → первый сохраняет → второй получает 409 → обновляет версию без потери текста → сохраняет и явно публикует. Старое опубликованное содержимое сохраняется до публикации, после отзыва права формы исчезают.
- Браузер показал слишком крупные чекбоксы получателей и сжатие колонок сводной до букв. Чекбоксы имеют нормальный размер и область нажатия 44px; таблица имеет минимальную читаемую ширину и отдельную фокусируемую область прокрутки.
- Сохранено создание/чтение/правка/удаление старых гайдов, добавлена недостающая кнопка удаления нового материала по `delete_material`. Мок удаления больше не требует неописанный в клиентском контракте payload и проверяет отдельное право удаления.

## Автоматическая приёмка

В `frontend/`, с Node из локального runtime:

```sh
./node_modules/.bin/eslint .
./node_modules/.bin/tsc -b
./node_modules/.bin/vitest run
./node_modules/.bin/vite build
```

Результат: **103 теста в 12 файлах успешны**, lint, TypeScript и production build успешны. Live integration suite не запускалась.

Новые связанные сценарии в `acceptance-followup.test.tsx`:

- Через формы: новая задача двум людям → начало своей работы руководителем → первая сдача → доработка → повторная сдача → приёмка. Обе сдачи сохранены, другое назначение остаётся независимым, дата выполнения взята из сдачи.
- Два независимых редакторских QueryClient с одной синтетической ролью и общим серверным состоянием (реальные разные аккаунты — отдельная интеграция): конфликт отчёта, сохранение обоих локальных текстов, явное обновление версии и публикация. Затем сервер отзывает редактирование, обе страницы перечитываются и убирают форму/черновик.
- Конфликт даты/критерия задачи, обновление версии без потери ввода, успешная повторная отправка.
- Через доступные маршруты: создание нового материала, правка черновика, публикация, удаление, возврат в каталог.
- Старый гайд: предупреждение о немедленной публикации, сохранение Markdown с gallery/chip, повторный GET и удаление синтетической записи.
- Заявка HR: одно одобрение через интерфейс, без второго этапа.
- Сохранён отдельный запрос/экран ПГАС и отсутствие управления у обычного участника.

В production проверены 24 JS-артефакта: отсутствуют `profkom-demo-role`, `profkom-demo-scenario`, `mock_not_implemented`, `synthetic_score`, `axios-mock-adapter`, временный phone harness и source maps. Контраст пар цветов четырёх решений: 10,58 / 9,87 / 11,08 / 11,09 к 1.

## Открытые зависимости и условия снятия

| Зависимость | Что требуется | Когда можно закрыть |
| --- | --- | --- |
| Старые гайды → материалы | Явная связь guide_id → material_id либо согласованные совместимые операции черновика/публикации `/guides`; права старого документа, включая глобальные назначения | Связь согласована, клиент использует её без угадывания; старый URL открывает правильный документ, читатель видит прежнюю публикацию, редактор сохраняет черновик и явно публикует |
| История закрытой сводной/аудит | Согласованный read API по ID/версии с автором, датой, причиной, ACL | Получение реальных предыдущих версий и аудита, затем проверка интерфейса их чтения |
| Реальный API и конкурентные записи | Совпадающие DTO, capabilities, revisions, ошибки; хранение, серверный расчёт и снимок состава | Настоящие запросы и повторный GET, вторая роль/запрет доступа, 409 без перезаписи; реальная конкуренция аккаунтов |
| Файлы/аватары/VK | Настоящие сервисы, complete/download и проверка принадлежности | Реальный успешный поток и отрицательная проверка доступа; сохранение после повторного входа |
| XLSX | Настоящая серверная выгрузка | Файл открывается, два согласованных листа, значения реального расчёта |

Произвольный балл, формула ККР, рейтинг, стаж и автоматическое право подмены в браузере не добавлены. Реальный API, S3/VK, XLSX и производственный деплой не заявляются готовыми.
