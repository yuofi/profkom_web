# Удаление очередей

`DELETE /api/task-queues/{queue_id}` принимает `expected_revision` и логически
удаляет очередь в одной транзакции. Права задаёт `queue.delete` в `access.POLICY`:
председатель, его заместители, мастер HR, мастер блока / ответственный команды
данной очереди, её явно назначенный владелец и сервисный аккаунт. Обычное
заместительство мастера или ответственного само по себе этого права не даёт.
Сначала проверяется существующий доступ к объекту: назначение мастером не
раскрывает частную очередь, к которой у него нет доступа. ККР и WEBSUPPORT,
а также очередь, привязанная к конфигурации поддержки, удалять нельзя.

Очередь получает `deleted_at`, `deleted_by_user_id` и следующую ревизию;
в `audit_logs` сохраняются время, автор и прежний статус default. Ожидающие
запросы доступа отменяются с тем же временем и автором. Повторное удаление
возвращает 404, устаревшая ревизия — 409; запрещённая команда ничего не меняет.

Очередь исчезает из каталога и вариантов создания задач. Изменение параметров,
новые задачи и новые запросы доступа запрещены. Задачи, их номера, ККР,
назначения, история и действующие права сохраняются. В «Все задачи» остаются
доступные пользователю задачи. По ссылке из задачи по-прежнему открывается
удалённая очередь с пояснением и сохранёнными задачами. Владелец и сервисный
аккаунт могут просмотреть прежние запросы и отозвать существующие разрешения;
одобрить новый доступ нельзя. Автоматическая передача недоступного владельца
сохраняется и для удалённой очереди: частные задачи не остаются без управления.

Ключ удалённой очереди занят навсегда, чтобы старые номера не обозначали новые
задачи. При удалении default-очереди её флаг сбрасывается; следующая операция,
которой нужна default-очередь команды, создаёт новую с другим ID и ключом.
Startup-миграция только добавляет nullable-колонки, повторяется безопасно и
не меняет существующие строки. Откат старого приложения на БД с уже удалёнными
очередями требует осторожности: старый код не фильтрует tombstone-строки и снова
покажет их. База не восстанавливается автоматически при откате образа.

Проверки: `test_queue_deletion.py` (права, ревизии, сохранность, отзыв старого
доступа, повторный startup старой схемы), `test_queue_catalog_reads.py` (границы
числа SQL-запросов), `queue-deletion.test.tsx` (подтверждение и конфликты).
