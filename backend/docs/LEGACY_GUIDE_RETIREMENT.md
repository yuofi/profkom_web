# АВ-11/37: старые гайды переведены на материалы

Согласованная граница: иных потребителей API гайдов нет; дублирующие CRUD и
редакторы убираются. Числовой id старого гайда, исходная строка `guides` и
соответствие `materials.legacy_guide_id` сохраняются. Это миграционные данные,
а не второй действующий API редактирования.

## Инвентаризация потребителей

До изменения действующий App открывал `/guides`, `/docs/:id` и
`/docs/:id/edit` через `GuidesPage`, `DocViewerPage`, `DocEditPage` и
`GuideEditRoute`; редактор сначала запрашивал старый guide DTO и потом обычно
переходил к материалу. Невостребованный fallback мог публиковать напрямую.
`GuidesManagement` использовался только старыми тестами после переноса
административных вкладок. `Layout/Navbar`, `useGuides`, `presetDB`,
`guides.api`, `docs.api`, `canEditGuide` обслуживали этот же старый путь.

Эти потребители удалены. `ProtectedRoute` остаётся общим барьером сессии.
Текущий `MarkdownContent` по-прежнему использует `Gallery` и `ContactChip`
для отображения сохранённых исторических вставок; их удаление повредило бы
материалы. Неподключённые TipTap extensions удалены, зависимости редактора
не меняются в этом шаге.

## Матрица совместимости

| Ссылка/состояние | Результат после переноса | Проверяемая граница |
| --- | --- | --- |
| `/guides` | `/materials?kind=guide` | Текущий каталог, без старой панели |
| `/docs/:id`, `/guides/:id` | разрешение id → `/materials/:material_id` | Публикация и прежние вложения читаются |
| `/docs/:id/edit` | тот же материал в обычном режиме чтения | Редактирование только явным карандашом |
| `/admin/guides`, `/admin/materials` | соответствующий фильтр каталога | Старые административные формы отсутствуют |
| Опубликованный общий гайд | читается одобренным активистом | Markdown/старый HTML преобразованы без утраты данных |
| Гайд закрытого блока | доступен по действующим правам блока | Постороннему 404 и отсутствие раскрытия material id |
| Только черновик | виден редактору; обычному читателю 404 | draft не становится публикацией при переходе |
| Сохранённый общий черновик | читатель видит прежнюю публикацию | сохранение и публикация остаются разными командами |
| Удалённый/несуществующий гайд | 404 | URL не восстанавливает материал и не создаёт новый id |
| `file:<id>` в исходнике | тот же id и contextual owner | чтение файла перепроверяет его текущий ACL |
| Старая URL загрузки | сохраняется как историческая строка | миграция не обращается к внешнему хранилищу |

`GET /api/materials/legacy-guides/{guide_id}` возвращает только
`{guide_id, material_id, revision}` и применяет `materials.can_read`.
Несанкционированный доступ, удалённый материал и неизвестный id дают 404.
Обновление, публикация, редакторы и удаление выполняются исключительно
через `/api/materials` с прежними ревизиями и правами.

Семейство `/api/guides` (GET списка/объекта/старого mapping, POST, PUT,
PATCH, DELETE) удалено из маршрутизатора и OpenAPI. Оно не перенаправляет
запросы изменения, не изменяет данные и не имеет fallback публикации.

## Приёмка

Backend `test_guides.py` проверяет матрицу доступа к resolver и сохранность
id/источника/вложений, отсутствие старых методов и приватность draft.
`test_v13_materials`, `test_file_delivery`, `test_storage_links` продолжают
проверять прежние публикационные и файловые ограничения через текущий API.
Frontend `legacy-material-redirect.test.tsx` проверяет обе старые ссылки,
ошибку доступа и отсутствие вызовов старого API. HTTP/DOM
`legacy-guide.integration.test.tsx` проходит сохранение отдельного черновика
и публикацию через реальный API. Исторические строки для тестов импортирует
только nonce-gated `/_test/legacy-guides` одноразового loopback harness;
в production приложение этот route не регистрируется.
