Как работает авторизация VK ID на Web

Мы предлагаем четыре способа авторизации:
  • через SDK для публичных приложений: с обменом кода на фронтенде;
  • через SDK для конфиденциальных приложений: с обменом кода на бэкенде;
  • без SDK для публичных приложений: с обменом кода на фронтенде;
  • без SDK для конфиденциальных приложений: с обменом кода на бэкенде.
Подробнее о конфиденциальных и публичных приложениях

Через SDK с обменом кода на фронтенде

Схема работы авторизации через SDK для Web с обменом кода на фронтенде
  1. Пользователь инициирует процесс авторизации: нажимает кнопку Войти через VK ID.
  2. Партнер вызывает метод VKID.Auth.login() из VK ID SDK.
  3. VK ID SDK генерирует набор параметров PKCE, необходимых для защиты передаваемых данных, а также state и scopes:
    • code_verifier — случайно сгенерированная строка, новая на каждый запрос авторизации. Может состоять из следующих символов: a-z, A-Z, 0-9, _, -. Длина от 43 до 128 символов;
    • code_challenge — зашифрованный code_verifier;
    • code_challenge_method — метод шифрования code_verifier, константа. Всегда принимает значение S256;
    • state — произвольная строка состояния приложения;
    • scopes — список названий прав доступа, которые необходимы приложению в процессе получения токена. Если параметр не указан, то берётся минимальное значение прав доступа по умолчанию — vkid.personal_info.
  4. VK ID SDK открывает ссылку https://id.vk.ru/authorize во вкладке браузера, используя несколько параметров. Основные из них:
    • response_type=code — требуемый ответ. При запросе кода подтверждения следует указать значение code;
    • client_id — ID приложения, полученный при создании приложения;
    • redirect_uri — адрес для возврата в приложение Партнёра.
    Также используются параметры code_challenge, code_challenge_method и state.
  5. Пользователь проходит аутентификацию.
  6. Пользователю отображается форма с разрешением на предоставление доступов приложению, и он разрешает доступ.
  7. Запрос на предоставление доступов приложению Партнёра передается в VK ID.
  8. VK ID генерирует код авторизации.
  9. VK ID передаёт через postMessage код авторизации, state, созданный на шаге 3, а также device_id.
  10. VK ID SDK проверяет полученный state.
  11. VK ID SDK возвращает Партнеру параметры code, state и device_id.
  12. Чтобы обменять авторизационный код на токены, Партнер использует метод SDK VKID.Auth.exchangeCode(code, device_id), передав туда code и device_id, которые получены после авторизации.
  13. В ответ на код авторизации VK ID возвращает набор токенов: Access token + Refresh token + ID token.
  14. Партнер получает Access token — авторизация успешно завершается.

Через SDK с обменом кода на бэкенде

Перед настройкой этого способа убедитесь, что в кабинете сервиса авторизации VK ID для приложения указано, что оно конфиденциальное.
Схема работы авторизации через SDK для Web с обменом кода на бэкенде
Обратите внимание
Генерировать параметры PKCE нужно на фронтенде, а передавать на бэкенд — только при обмене кода на токены. Полученные токены рекомендуем оставить на бэкенде.
  1. Пользователь инициирует процесс авторизации: нажимает кнопку Войти через VK ID.
  2. Frontend Партнёра генерирует набор параметров PKCE, необходимых для защиты передаваемых данных, а также state и scopes:
    • code_verifier — случайно сгенерированная строка, новая на каждый запрос авторизации. Может состоять из следующих символов: a-z, A-Z, 0-9, _, -. Длина от 43 до 128 символов;
    • code_challenge — зашифрованный code_verifier;
    • code_challenge_method — метод шифрования code_verifier, константа. Всегда принимает значение S256;
    • state — произвольная строка состояния приложения;
    • scopes — список названий прав доступа, которые необходимы приложению в процессе получения токена. Если параметр не указан, то берётся минимальное значение прав доступа по умолчанию — vkid.personal_info.
  3. Frontend Партнёра передаёт code_challenge и state в VK ID SDK через инициализацию VKID.Config.init().
  4. Партнер вызывает метод VKID.Auth.login() из VK ID SDK.
  5. VK ID SDK открывает ссылку https://id.vk.ru/authorize во вкладке браузера, используя несколько параметров. Основные из них:
    • response_type=code — требуемый ответ. При запросе кода подтверждения следует указать значение code;
    • client_id — ID приложения, полученный при создании приложения;
    • redirect_uri — адрес для возврата в приложение Партнёра.
    Также используются параметры code_challenge, code_challenge_method и state.
  6. Пользователь проходит аутентификацию.
  7. Пользователю отображается форма с разрешением на предоставление доступов приложению, и он разрешает доступ.
  8. Запрос на предоставление доступов приложению Партнёра передается в VK ID.
  9. VK ID генерирует код авторизации.
  10. VK ID передаёт через postMessage код авторизации, state, созданный на шаге 3, а также device_id.
  11. VK ID SDK проверяет полученный state.
  12. VK ID SDK возвращает на Frontend партнёра параметры code, state и device_id.
  13. Frontend Партнёра передаёт code, state, code_verifier, device_id на свой Backend.
  14. Чтобы обменять авторизационный код на токены, Backend Партнёра использует метод API id.vk.ru/oauth2/auth, где grant_type = authorization_code. В качестве аргументов использует code, code_verifier и device_id, которые получены после авторизации. Также для конфиденциальных приложений необходимо передавать service_token.
  15. В ответ на код авторизации VK ID возвращает набор токенов: Access token + Refresh token + ID token.
  16. Партнер получает Access token — авторизация успешно завершается.

  2. Партнер запускает процесс авторизации.

  4. Партнер открывает ссылку https://id.vk.ru/authorize во вкладке браузера, используя несколько параметров. Основные из них:

    Также используются параметры code_challenge, code_challenge_method и state.
  5. Пользователь проходит аутентификацию.
  6. Пользователю отображается форма с разрешением на предоставление доступов приложению, и он разрешает доступ.
  7. Запрос на предоставление доступов приложению Партнёра передается в VK ID.
  8. VK ID генерирует код авторизации.

  13. Партнер получает Access token — авторизация успешно завершается.

Дальнейшие шаги

  • Установите VK ID SDK и настройте элементы быстрого входа в ваше приложение: кнопку One Tap, шторку авторизации, виджет 3 в 1 или всё сразу. Для приложения на платформе Web это можно сделать с помощью Low-code — инструмент сгенерирует готовый код для вставки, где используется установка SDK через скрипт. Если этот способ вам не подходит — установите VK ID SDK через пакетный менеджер.
  • Или воспользуйтесь авторизацией без SDK для Web.
