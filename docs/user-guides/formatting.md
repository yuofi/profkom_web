```profkom-html id=embed-format-start
<section class="guide-card guide-gradient-info">
<h2>Оформление без сложной вёрстки</h2>
<p>Markdown отвечает за основной текст. Готовые HTML-вставки добавляют плашки, кнопки, таблицы, изображения и раскрывающиеся ответы. Начните с простого текста и добавляйте оформление там, где оно помогает читателю.</p>
</section>
```

Как создать материал, назначить редакторов и опубликовать черновик — в [гайде для авторов](GUIDE_AUTHORING). Здесь собраны синтаксис, примеры и границы возможностей редактора.

## Markdown: повседневный набор

Пишите обычный текст, а специальные символы используйте для структуры и выделения. Панель редактора помогает вставить оформление; тот же результат можно набрать вручную.

| Что нужно | Как записать |
| --- | --- |
| **Полужирный текст** | `**Полужирный текст**` |
| *Курсив* | `*Курсив*` |
| ~~Зачёркнутый текст~~ | `~~Зачёркнутый текст~~` |
| `Короткий фрагмент кода` | Обрамить обратными кавычками: `` `код` `` |
| Ссылка | `[Подпись](https://example.org)` |
| Цитата | Начать строку с `> ` |
| Пункт списка | Начать строку с `- ` |
| Нумерованный шаг | Начать строку с `1. ` |
| Разделитель | Отдельная строка `---` |

Оставляйте пустую строку между абзацами и перед списком. В редакторе поддерживается и обычный перенос строки, но он не заменяет смысловое разделение абзацев.

```markdown
**Перед началом:** подготовьте название и краткое описание.

1. Откройте материалы.
2. Создайте черновик.
3. Проверьте предпросмотр.

> Совет: называйте кнопку так, как она называется на сайте.
```

Для чек-листа используется `- [ ]` и `- [x]`:

```markdown
- [x] Черновик создан
- [ ] Ссылки проверены
- [ ] Материал опубликован
```

В опубликованном гайде это **отображение списка**, а не личный интерактивный прогресс читателя. Интерактивные чек-листы в других частях сайта имеют свой отдельный сценарий.

Если символ мешает и превращается в оформление, экранируйте его обратной косой чертой: `\*` покажет обычную звёздочку.

## Заголовки и оглавление

Название материала уже стоит вверху страницы. Внутри текста начинайте основные разделы с `##`, а подразделы — с `###`:

```markdown
## Подготовка
Текст раздела.

### Что понадобится
Текст подраздела.
```

Сайт автоматически строит оглавление по заголовкам, поэтому повторять список разделов в начале текста не нужно. Для перехода из абзаца или кнопки можно добавить отдельную ссылку. Внутренние ссылки на обычные Markdown-заголовки имеют вид `#section-1`, `#section-2` и так далее — по порядку всех заголовков, включая подразделы.

Например, если первый заголовок — «Подготовка», а второй — «Что понадобится», ссылка `[Что понадобится](#section-2)` ведёт ко второму. Если всё же добавляете свой короткий список переходов, его подпись можно сделать полужирной, чтобы она не занимала номер заголовка.

Заголовки внутри HTML-вставки получают отдельные адреса: у вставки `id=embed-example` это `#embed-example-heading-1`, затем `#embed-example-heading-2`. Номера обычных Markdown-разделов и заголовков вставки не смешиваются.

Проще выбирать раздел в конструкторе кнопки. После перестановки или добавления заголовков перепроверьте переходы: прежний номер может начать указывать на другой раздел. Не добавляйте собственный HTML-атрибут `id` — он не поддерживается.

## Ссылки и изображения

**Ссылка с понятной подписью:**

```markdown
[Открыть трекер](/tasks)
[Открыть материалы](/materials)
[Сайт организации](https://example.org)
```

Для ссылки на другой гайд скопируйте его адрес или выберите опубликованный гайд в конструкторе кнопки. Ссылка не меняет права доступа: закрытый материал останется закрытым для читателя без нужных прав.

**Изображение в Markdown:**

```markdown
![Экран редактора с кнопкой сохранения](file:file-example)
```

`file:file-example` — образец. Замените его ссылкой на реально загруженный в этот материал файл; не печатайте вымышленный идентификатор в рабочем гайде. Текст в квадратных скобках описывает содержание картинки и помогает, если она не загрузилась или читатель использует экранный диктор.

Для изображения с подписью и управляемыми размерами удобнее **«Вставить → Изображение»**. Такие HTML-вставки принимают PNG, JPEG или WebP из файлов текущего материала.

Для нескольких картинок есть Markdown-галерея: каждая строка содержит файл и необязательную подпись после `|`.

````markdown
```gallery
file:file-first | Первый шаг: открываем редактор
file:file-second | Второй шаг: сохраняем черновик
```
````

Здесь идентификаторы тоже только образцы; подставьте реальные файлы этого гайда. Не переносите в общий материал ссылки на чужие закрытые вложения.

## Таблицы, код и формулы

Для простой таблицы достаточно Markdown:

```markdown
| Действие | Что происходит |
| --- | --- |
| Сохранить черновик | Сохраняется рабочая версия |
| Опубликовать | Читатели получают сохранённую версию |
```

Вертикальная черта отделяет ячейки. Если она нужна внутри текста ячейки, используйте `\|`. Большие сравнительные таблицы лучше делить на несколько небольших.

Блок кода открывается и закрывается тремя обратными кавычками. После первых можно написать язык, например `python`, `json` или `html`, чтобы включить подсветку:

````markdown
```json
{"example": "Это иллюстрация, а не команда сайту"}
```
````

Если нужно показать пример, внутри которого уже есть тройные кавычки, обрамите его **четырьмя**. В этом справочнике именно так показаны образцы HTML-вставок: они остаются кодом для копирования, а не исполняемым оформлением.

Поддерживаются формулы в синтаксисе TeX: `$a^2 + b^2 = c^2$` в строке и отдельный блок между `$$`. Например:

```text
$$
\frac{1}{2} + \frac{1}{2} = 1
$$
```

Формулы нужны там, где обычная запись действительно неудобна. Если требуется буквальный знак доллара в тексте, используйте `\$`.

## Как включить HTML-вставки

Оформленные вставки доступны в **сохранённом гайде блока** при наличии права редактирования. Нажмите **«Вставить»**, выберите тип и подтвердите **«Включить оформленные вставки в этом гайде»**. После вставки сохраните черновик и проверьте предпросмотр.

Одна вставка в исходном тексте выглядит так:

````markdown
```profkom-html id=embed-example
<section class="guide-card guide-tone-info">
  <h3>Полезный совет</h3>
  <p>Сначала сохраните черновик, затем проверьте результат.</p>
</section>
```
````

Это ограниченный набор HTML для оформления материала. Обычный блок `html` остаётся примером кода; произвольный HTML, вписанный прямо в Markdown, не включается. В обычном формате материала даже блок `profkom-html` останется кодом до явного включения вставок.

У каждой вставки должен быть **уникальный идентификатор** после `id=`: латинская строчная буква в начале, дальше строчные латинские буквы, цифры и дефисы; всего до 64 символов. Конструктор создаёт его автоматически. При копировании примеров меняйте повторяющиеся идентификаторы.

Markdown внутри HTML-вставки не обрабатывается как обычная разметка. Вместо `**важно**` пишите `<strong>важно</strong>`, вместо Markdown-ссылки — `<a href="…">подпись</a>`.

## Плашки, цвета и градиенты

Базовый класс карточки — `guide-card`. К нему добавляется одна тема:

| Класс | Вид и подходящее применение |
| --- | --- |
| `guide-tone-neutral` | Нейтральная тёмная карточка для дополнительных сведений |
| `guide-tone-info` | Светлая голубая плашка для объяснения или совета |
| `guide-tone-success` | Мятная плашка для готового результата и проверки |
| `guide-tone-warning` | Персиковая плашка для условия, которое легко пропустить |
| `guide-gradient-info` | Мягкий переход от сиреневого к голубому |
| `guide-gradient-success` | Переход от мятного к светлому фирменному цвету |
| `guide-gradient-warning` | Переход от сиреневого к персиковому |

Дополнительно: `guide-compact` делает блок компактнее; `guide-align-left`, `guide-align-center`, `guide-align-right` задают выравнивание текста.

```profkom-html id=embed-format-tones
<div class="guide-grid-2">
<section class="guide-card guide-tone-info guide-compact"><h3>Совет</h3><p>Один акцент помогает найти важное.</p></section>
<section class="guide-card guide-gradient-warning guide-compact"><h3>Перед публикацией</h3><p>Проверьте ссылки и мобильную ширину.</p></section>
</div>
```

Код второй карточки:

```html
<section class="guide-card guide-gradient-warning guide-compact">
  <h3>Перед публикацией</h3>
  <p>Проверьте ссылки и мобильную ширину.</p>
</section>
```

Произвольные HEX-цвета, собственный CSS, `style="…"`, фоновая картинка через CSS и подключение шрифтов не поддерживаются. Используйте готовые темы: они согласованы с сайтом и сохраняют читаемость.

## Кнопки и переходы

Кнопка в гайде — это **ссылка для перехода**, оформленная как кнопка. Она не отправляет форму, не изменяет данные и не запускает JavaScript.

```profkom-html id=embed-format-buttons
<section class="guide-card guide-tone-neutral">
<h3>Переход без поиска по меню</h3>
<p><a class="guide-button" href="/tasks">Открыть трекер</a><a class="guide-button guide-button-secondary" href="/materials">Все материалы</a></p>
</section>
```

Код таких переходов:

```html
<p>
  <a class="guide-button" href="/tasks">Открыть трекер</a>
  <a class="guide-button guide-button-secondary" href="/materials">Все материалы</a>
</p>
```

В конструкторе можно выбрать внешний сайт, другой опубликованный гайд или раздел текущего. В HTML поддерживаются:

- Полный адрес `https://example.org/page` — внешний переход открывается отдельно и помечается как внешний.
- Путь сайта, например `/tasks` или адрес материала.
- Якорь существующего заголовка, например `#section-1`.

Не используйте адреса служебных API, `javascript:`, ссылки с логином и паролем, `http://` для внешнего сайта или произвольные псевдопротоколы. Для перехода внутри гайда выбирайте заголовок, а не придумывайте якорь.

## Колонки, шаги и раскрывающиеся ответы

**Колонки.** Оберните карточки в `<div class="guide-grid-2">` или `guide-grid-3`. На узком экране они станут одной колонкой. Не используйте сетку для длинных последовательных инструкций: читателю проще идти сверху вниз.

```html
<div class="guide-grid-2">
  <section class="guide-card guide-tone-neutral">
    <h3>До начала</h3>
    <p>Подготовьте материалы.</p>
  </section>
  <section class="guide-card guide-tone-success">
    <h3>В результате</h3>
    <p>Получится опубликованный гайд.</p>
  </section>
</div>
```

**Шаги.** Используйте нумерованный список `<ol>` с пунктами `<li>`. Внутри пункта можно выделить название через `<strong>` и дать пояснение в `<p>`.

**Раскрывающийся ответ.** Нужны `<details>` и первый непустой `<summary>`. Например:

```profkom-html id=embed-format-faq
<details class="guide-card guide-tone-neutral">
<summary>Нужно ли знать HTML, чтобы сделать плашку?</summary>
<p>Нет. Выберите «Вставить → Плашка» и заполните поля. Режим HTML пригодится для собственной композиции из разрешённых элементов.</p>
</details>
```

Его код:

```html
<details class="guide-card guide-tone-neutral">
  <summary>Нужно ли знать HTML?</summary>
  <p>Нет, можно использовать готовую форму вставки.</p>
</details>
```

Не прячьте внутри раскрывающегося ответа обязательный шаг: его легко пропустить. Туда подходят дополнительные объяснения и редкие ситуации.

## HTML-таблицы и картинки

HTML-таблица позволяет задать подпись и заголовки явно. У каждой таблицы обязателен непустой `<caption>`.

```html
<table>
  <caption>Что увидят читатели</caption>
  <thead><tr><th scope="col">Состояние</th><th scope="col">Результат</th></tr></thead>
  <tbody>
    <tr><td>Только черновик</td><td>Материал ещё не опубликован</td></tr>
    <tr><td>Опубликован</td><td>Доступна опубликованная версия</td></tr>
  </tbody>
</table>
```

Для компактной таблицы добавьте `class="guide-compact"`. Допускаются `colspan` и `rowspan` от 1 до 20, но объединённые ячейки стоит использовать только при реальной необходимости. На телефоне широкая таблица прокручивается внутри своего блока.

Для картинки с подписью используйте такую структуру:

```html
<figure class="guide-align-center">
  <img src="file:file-example" alt="Редактор материала и кнопка сохранения" width="960" height="640">
  <figcaption>После правок сохраните черновик.</figcaption>
</figure>
```

Здесь `file:file-example` — образец, не готовая картинка. Используйте реальный файл, загруженный в этот материал. Обязательны `src`, непустой `alt`, `width` и `height`; размеры — целые числа от 1 до 4096. Указывайте пропорции исходного изображения. На узком экране картинка уменьшится автоматически.

Во вставках не допускаются внешние ссылки вместо `src`, SVG, произвольный `data:` и файлы другого материала. Форматы для изображения — PNG, JPEG и WebP.

## Что разрешено и что ограничено

**Поддержанные HTML-элементы:**

- Структура: `section`, `div`, `p`, `span`, `h2`–`h6`, `br`, `hr`.
- Текст: `strong`, `em`, `s`, `mark`, `small`, `sub`, `sup`, `blockquote`, `pre`, `code`.
- Списки: `ul`, `ol`, `li`, `dl`, `dt`, `dd`.
- Таблицы: `table`, `caption`, `thead`, `tbody`, `tfoot`, `tr`, `th`, `td`.
- Раскрывающиеся блоки: `details`, `summary`.
- Ссылки и изображения: `a`, `figure`, `figcaption`, `img`.

В HTML используйте `&amp;`, `&lt;`, `&gt;` для буквальных `&`, `<`, `>` там, где они могут восприниматься как разметка. Закрывайте парные теги. Разрешены только перечисленные готовые классы и поддержанные атрибуты; произвольные `id`, `style`, обработчики событий и HTML-комментарии не принимаются.

**Не поддерживаются:** JavaScript, iframe, встраивание стороннего сайта или видео-плеера, формы ввода, скриптовые виджеты, SVG/MathML внутри HTML, собственные стили и внешние таблицы стилей. Вместо встраивания стороннего сервиса дайте подписанную HTTPS-ссылку.

Ограничения размера рассчитаны на гайд, а не на целую самостоятельную веб-страницу:

| Ограничение | Значение |
| --- | ---: |
| Оформленные вставки на материал | До 20 |
| Размер одной HTML-вставки | До 32 КиБ |
| Суммарный HTML вставок | До 128 КиБ |
| Элементы в одной вставке | До 300 |
| Элементы во всех вставках | До 1500 |
| Вложенность | До 12 уровней |
| Изображения в одной вставке | До 4 |
| Изображения во всех HTML-вставках | До 20 |

Если проверка показывает ошибку, она указывает строку и причину. Исправьте вставку и повторите предпросмотр. Некорректное оформление можно оставить в черновике, но публикация потребует устранить ошибки.

## Как сохранить удобство и скорость

1. **Основной текст оставляйте в Markdown.** Для нескольких цветных акцентов достаточно нескольких небольших вставок.
2. **Уменьшайте картинки до полезного размера.** Скриншот кнопки не требует полноразмерного снимка всего рабочего стола. Предпочитайте чёткий обрезанный кадр с подписью.
3. **Не повторяйте тяжёлые изображения.** На тот же файл можно сослаться; для новой темы лучше отдельный материал.
4. **Избегайте огромных таблиц и глубокой вложенности.** Делите материал по задачам читателя, а не по максимально допустимому числу элементов.
5. **Проверяйте телефонный предпросмотр.** Кнопки должны легко нажиматься, а текст — читаться без увеличения.
6. **После сохранения проверьте опубликованную страницу.** Предпросмотр и публикация — разные шаги; ссылки и файлы должны работать у нужной аудитории.

```profkom-html id=embed-format-finish
<section class="guide-card guide-tone-success">
<h3>Хорошее оформление помогает действовать</h3>
<p>Если читатель быстро нашёл нужный раздел, понял следующий шаг и увидел результат — гайд оформлен удачно. Цвет, колонки и кнопки должны помогать этому маршруту.</p>
</section>
```
