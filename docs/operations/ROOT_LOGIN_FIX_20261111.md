## Причина

В production подтверждены десять HTTP500 на `/api/auth/login` с
`sqlalchemy.orm.exc.StaleDataError` в `service_account.reserve()`.
Одна сервисная учётная запись существует, backend не перезапускался,
`integrity_check=ok`; ошибка возникала ещё до проверки пароля.

При пропуске минимум двух 15-минутных окон ORM обновляла окно счётчика в памяти.
Из-за отключённого autoflush следующая bulk-очистка видела прежнее, просроченное
окно в SQLite и удаляла эту же строку. Последующий flush пытался обновить уже
несуществующую запись и возвращал500. Проверка предыдущего единственного окна
в старом тесте этот случай не покрывала.

Перед bulk-очисткой добавлен `session.flush()` внутри той же транзакции.
Обновлённая строка клиента сохраняется, прочие старые строки удаляются, лимит
попыток и отказ неверному паролю продолжают действовать.
