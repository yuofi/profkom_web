## Сертификат

Compose монтирует `/etc/letsencrypt:/etc/letsencrypt:ro`; nginx читает
`/etc/letsencrypt/live/profcom-cmc.ru/fullchain.pem` и `privkey.pem`.
Весь каталог сохраняет symlink-цепочку `live`→`archive`; ключ не включён в образ.
Прежний custom daemon копирования сертификатов не переносился.

Certbot переведён со standalone на webroot `/var/lib/profkom-acme`, доступный
nginx как `/var/www/certbot:ro`. Challenge проверен по IPv4/IPv6;
`certbot reconfigure` успешно выполнил staging-проверку, действующий сертификат
не заменялся. Timer активен; deploy-hook `profkom-nginx-reload` проверяет nginx
и выполняет reload после продления. Это штатная схема
[Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html#modifying-the-renewal-configuration),
без освобождения порта80 остановкой сайта.

## Откат после публичного запуска

Новый сайт уже принимает записи. **Нельзя просто включить старую базу** или
восстановить финальный snapshot поверх новых действий пользователей.

При необходимости сначала остановить новых writers в порядке bot→site,
передать последний отчёт бота, снять новые SQLite backup API и PostgreSQL dumps,
проверить обратный перенос либо исправить новый узел. Возврат на старый сервер
требует также переключения маршрутизации; DNS сейчас ведёт на новый.
VPN-маршруты должны сохраняться при любом варианте.

Старый `/root/profkom-migration-20261110/site-old-stop2/rollback-before-new-writes.py`
предназначен только для состояния до новых записей либо после проверенного
обратного переноса. Его флаг подтверждения не заменяет эту проверку.
Обратный P2B PATCH возможен отдельно с актуальной revision, без восстановления
всей БД. `docker compose down`, удаление volumes/images и очистка backups
в этой миграции не выполнялись.
