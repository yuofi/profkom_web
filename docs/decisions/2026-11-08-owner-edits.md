# Решения владельца: правки ККР, шаблонов, трекера, рассылок и служебный аккаунт, 8 ноября 2026

> Датированная запись ответов владельца на разбор правок. Номера пунктов — как в разборе:
> А — учёт ККР, Б — заслуги и шаблоны, В — трекер. Запись не разрешает внешних действий:
> вся работа локальная (AGENTS.md).

## Учёт ККР на задаче

| Пункт | Решение |
| --- | --- |
| А1. Галочки вместо «Да/Нет» | Везде, где заполняют критерии: форма заслуги, исправление закрытых итогов, редактор шаблона. Названия критериев одинаковые на всех экранах |
| А1. Набор критериев | Привести в соответствие с таблицей владельца: восемь признаков со своими множителями (ниже). К пяти прежним добавляются «Срочная задача», «Нудная / монотонная задача» и «Требуется ли физическая сила». В старых записях новых признаков нет, их итоги не меняются |
| А2. Кнопки учёта | Секция «Учёт работы и ККР» на задаче и окно учёта: кнопки открытия и сохранения слишком маленькие и не в стиле сайта. Варианты показать снимками |
| А3. «Позже» | Убрать. Окно закрывают ✕ и Esc, ККР при закрытии задачи остаётся необязательной |

## Учёт выполненной работы (особые заслуги и волонтёры)

| Пункт | Решение |
| --- | --- |
| Б1. Одинаковые значения для всех | «Председская ККР» — вся страница «Учёт выполненной работы». Галочка «одинаково для всех»: одни часы, оценка и дата на всех получателей, отдельного человека можно поправить |
| Б8. Список записей | Записей может быть много. Варианты оформления показать снимками |

## Шаблоны ККР

| Пункт | Решение |
| --- | --- |
| Б2. Авторство | Показывать автора и того, кто последним изменил шаблон. Дату создания не показывать |
| Б3. Чужие шаблоны | Создание уже ограничено командами, где человек ведёт ККР. При применении показывать только шаблоны этой команды, личные и «Весь Профком» |
| Б4. Фильтры | Поиск по названию, команда, личные/командные; архивные скрыты по умолчанию. Сезона у шаблона нет |
| Б5. Правка | Форма раскрывается прямо в карточке шаблона (отменяет размещение над списком из SE-27) |
| Б6. «Отвязать шаблон» | Убрать. Если сохранение не проходит из-за шаблона, сообщение предлагает сохранить без шаблона |

## Трекер

| Пункт | Решение |
| --- | --- |
| В1. Зависимости | Предупреждение держится, пока задача, от которой зависят, не «Закрыта» (как сейчас). В окне «Добавить связь» — подсказки о видах связи; пример показать снимком |
| В2. Цвета статусов | Раскрасить статусы связанных задач, подзадач и подобных списков, где статус сейчас простым текстом. Цвета календаря и диаграммы Ганта привязать к нынешним статусам |
| В3. Backspace в чеклисте | Backspace только стирает текст; пустой пункт удаляется крестиком «×» |
| В4. Чеклист в комментарии | Отмечать может любой читатель задачи; комментарий не помечается «изменён»; отметка видна в истории |
| В5. Удаление комментария | Через меню «⋯». Удалить может любой, кто может комментировать задачу. Заглушки не остаётся, удаление видно в истории задачи |
| В6. «Взять в работу», «Сдать результат» | Убрать везде, включая обращения в поддержку. Результат пишут в комментарии; блок «Результаты работы» остаётся только для уже сданных результатов |
| В7. ККР в аналитике | Не ошибка: за задачу выставилось 0 баллов |
| В8. Привязка очереди | Своего параметра у очереди нет. На странице очереди видно команду и сезон, если он есть у команды или мероприятия; если сезон мероприятия закрыт или подводит итоги, видно, что новые задачи создать нельзя |
| В9. Ключ очереди | Латинские заглавные буквы и цифры, первым символом — буква; строчные переводятся в заглавные |

## Рассылки

| Пункт | Решение |
| --- | --- |
| Понятные ошибки | Отказ показан на тестовом сайте под замом председателя. Воспроизводится только локально; если не воспроизводится — сообщить владельцу. Тексты отказов в рассылках — конкретные: кто может и к кому обратиться |

## Служебный аккаунт

| Пункт | Решение |
| --- | --- |
| Назначение | Для отладки. Нигде не отображается: ни в контактах, ни в выборе исполнителей и других списках людей |
| Вход | Только логин и пароль; логин `root`. Логин и хеш пароля задаются в `.env` сервера, без интерфейса на сайте; смена — правкой `.env` и перезапуском. Без VK ID и без привязки бота, срок обязательной привязки на него не действует |
| Права | Полный доступ ко всем функциям, включая консоль бота и действия «только председателя» |
| Подпись | В истории и уведомлениях — «Сервисный аккаунт» |
| Уведомление о входе | Только на сайте, председателю и мастеру блока IT: время, IP, браузер. О неудачных попытках — после трёх подряд |

### Критерии ККР и множители (таблица владельца)

| Признак | Множитель |
| --- | --- |
| Срочная задача | 1,5 |
| Задача уникальная | 1,2 |
| Нудная / монотонная задача | 1,2 |
| Задача требует творческого подхода | 1,3 |
| Требует общения с администрацией или людьми вне вуза | 1,1 |
| Требуется ли физическая сила | 1,2 |
| Требует очного присутствия | 1,2 |
| Выполняется в определённое время | 1,1 |

## Открытые вопросы

- А1: формула из шаблона (ARCHITECTURE_V13, «ККР: предоставленные правила») уже учитывает
  срочность в весе задачи: `hours * (1 + 1 / sqrt(available_days + 1))`. Галочка «Срочная
  задача ×1,5» пока добавляется к этому весу, автоматическая часть не меняется. Если галочка
  должна её заменить — ждёт ответа владельца.
- Варианты оформления снимками: А2, Б8, Б9, В1, В2, В5, В8, уведомление о входе служебного
  аккаунта.
- Б1: галочка «Одинаково для всех» сейчас по умолчанию выключена, и для новой записи тоже.
  Включать ли её сразу, когда получателей двое и больше?
- Служебный аккаунт и консоль бота: сервер обновлений берёт VK автора запроса
  (`deploy.sh request`), а у служебного аккаунта VK нет. Поэтому он смотрит консоль, ставит
  паузу, перезапускает бота и читает журнал, но обновление и откат получают отказ
  `bot_console_vk_required`. Оставить так или завести VK для таких запросов на сервере?
- Служебный аккаунт, вход: после 10 неудачных попыток с одного адреса за 15 минут вход под
  ним закрывается на время (429). У обычных аккаунтов ограничения попыток входа нет вовсе.
  Подходят ли цифры и нужно ли ограничение всем?
- Рассылки: отказ «http_403: Не удалось выполнить запрос» локально не воспроизводится. Его
  отдаёт не сайт, а что-то между браузером и API. Источник можно найти на сервере (журналы
  и `nginx` вне репозитория) только с отдельного разрешения владельца, или владелец сам
  смотрит тело ответа в DevTools → Network.
