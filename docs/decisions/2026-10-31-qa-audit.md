# Решения владельца: аудит 31 октября – 1 ноября 2026

> Датированная запись решений. Действующие правила — в [архитектуре](../../ARCHITECTURE.md),
> [TRACKER_WORKFLOW](../../backend/docs/TRACKER_WORKFLOW.md),
> [API_V13_ADDITIONS](../../backend/docs/API_V13_ADDITIONS.md) и [DEPLOY](../../DEPLOY.md);
> находки, проверки и коммиты — в [отчёте аудита](../audit/QA_AUDIT_20261031.md).
> Запись не разрешает внешних действий.

Решения приняты по ветке аудита `audit/qa-20261031` и вошли в `release-1` её слиянием.
Источник истины прав — `POLICY` в [access.py](../../backend/access.py); кнопки интерфейса
следуют `capabilities`.

## Доступ

| Пункт | Решение | Что заменяет |
| --- | --- | --- |
| SE-14 | Призыв к заполнению ККР (`kkr.remind`, capability `remind_kkr`) — только мастер HR и зам мастера HR, в открытом сезоне и на подведении итогов | Проверку вне `access.py`: призывал только мастер HR в любом состоянии сезона, а кнопку видели все читатели сводной |
| SE-13 | Закрытый сезон правят председатель, замы и мастер HR (`CLOSED_SEASON`): отметки, исправления, коэффициенты, публичные поля задач, исходные поля и даты оценивания, приёмка, заслуги, в том числе новые. Открытие, подведение итогов и закрытие сезона — по-прежнему только председатель | Закрытый сезон правили председатель и замы, отметки — только председатель |
| TR-05 | Новые строки учёта в закрытом сезоне (вступление, взятие, назначение, переназначение) добавляет тот же круг | Вступление и взятие задачи любым читателем создавали новые строки учёта |
| GL-09 | Зам мастера HR — обычный зам блока HR: очереди, гайд, карточка блока, задачи и состав; глобальные HR-этап заявок, ККР, сводная и аналитика сохранены; закрытый сезон он не правит. Отношение `HR_BLOCK_DEPUTY` убрано | Исключение, по которому зам HR в блоке HR не имел прав зама блока и не читал его гайд |
| PE-01 | Заместителей председателя, в том числе себя, архивирует и восстанавливает только председатель; обычные аккаунты — председатель и замы | Замы архивировали и восстанавливали друг друга |
| GL-22 | Автор тикета WEBSUPPORT сохраняет действия исполнителя; доступом к тикету делится только поддержка, `manage_task_access` у автора нет | Право управлять доступом у автора, все применения которого отклонялись |
| PB-16 | В открытом сезоне и на подведении итогов отметка сверяется с прежними отметками участника (`expected_decisions`), в закрытом — со строгой версией сводной | Отказ 409 при любом изменении версии сводной |
| SE-21 | Запланированный сезон отметок не принимает (403), сводная и выгрузка читаются | Меню отметок у сводной запланированного сезона |
| SE-26 | Верхнего предела коэффициента нет; значение больше 10 сохраняется только после подтверждения | Любое значение без предупреждения |
| PB-02 | Ответ команд трекера оставлен как есть | — |

## Поставка и производительность

| Пункт | Решение |
| --- | --- |
| PB-31 | SQLite в WAL с `synchronous=FULL` по строке `SQLITE_JOURNAL_MODE=WAL` в `backend/.env`; по умолчанию журнал DELETE. Включение на сервере — только с отдельного разрешения ([DEPLOY](../../DEPLOY.md), раздел 7) |
| PF-12 | gzip JSON-ответов `/api/`, кроме `/api/auth/` и выдачи файлов. На сервер — только по разрешению, которое называет PF-12 явно; иначе шаг выкладки убирает сжатие ([DEPLOY](../../DEPLOY.md), раздел 8) |
| PF-25 | Кнопка курсива — наклонная обычная «I», preload двух шрифтов woff2 |
| PF-03 | HTTP/2 в nginx — только отдельным исполнителем по [инструкции](../audit/PF-03/README.md), с разрешением на каждый шаг на сервере; клиентская склейка чанков уже в коде |

## Оформление (1 ноября)

Предложения по раскладке страниц [D-01–D-09](../audit/design-proposals-20261031/README.md)
одобрены все, с двумя правками: в D-02 чипы статуса выравниваются по длине (сейчас
«Выполнена» длиннее «В работе» и «Открыта»), и то же расхождение проверяется в других
местах; кнопка жучка (багрепорт) должна стоять в правом нижнем углу экрана на всех
страницах, в том числе на телефоне. Предложения применяются отдельной работой; пока она не
завершена, [образ интерфейса](../../ARCHITECTURE.md) описывает прежнюю раскладку, а README
предложений — их состояние до одобрения.
