# Решения владельца: связь сайта с ботом HereBot, 4 ноября 2026

> Датированная запись решений. Контракт обмена — [BOT_API](../../backend/docs/BOT_API.md).
> Запись не разрешает внешних действий: что разрешено — в разделе «Внешние действия».

## Что делаем

1. Уведомления сайта приходят в ЛС бота ВК
   ([HereBot_VK](https://github.com/profkomvmk/HeroBot_VK)).
2. Регистрация на сайте требует подключить бота: разрешить сообщения сообщества и выдать
   боту токен для его команд.
3. Консоль бота для мастера блока IT и назначенных им сопровождающих: статус, перезапуск,
   журнал, ошибки, обновление и откат.
4. Рассылки через бота всем пользователям сайта. Отправляют председатель, замы и
   назначенные ими люди.

База сайта остаётся на SQLite, база бота — на PostgreSQL. Общих таблиц и общего файла нет.

## Решения

| Пункт | Решение |
| --- | --- |
| Устройство | Бот — клиент API сайта `/api/bot/v1` по служебному токену. Сайт не обращается к VK и к боту внутри запросов пользователей, работа ждёт в очереди сайта |
| Одобренные аккаунты без бота | Баннер со сроком, после срока — обязательный шаг при входе (вариант Б) |
| Токен пользователя | Как в боте сейчас: тот же диалог, права `wall,offline`, хранение в `Tokens`. Дополнительного шифрования и выключателя обязательности нет |
| Что уходит в VK | Тип события, название объекта и ссылка; без комментариев, оценок и причин отказа. После привязки канал VK включён для категорий «трекер» и «заявки» |
| Рассылки в ленте сайта | Да: рассылка дублируется уведомлением на сайте |
| Блок IT | Блок с названием `IT`. Его мастер — корень доступа к консоли. Председатель консоль не видит |
| Обновление и откат из консоли | Да, через существующий канал обновлений бота (`deploy.sh request`) с теми же ограничениями, что из ЛС |
| Назначенные при смене руководителя | Сохраняются; новый мастер IT, председатель или зам видит список и снимает лишних |

Если блок IT переименуют, его мастер теряет доступ к консоли, пока блоку не вернут название;
назначенные сопровождающие доступ сохраняют.

Как этап 2 понимает обязательный шаг (подробно — [BOT_API.md](../../backend/docs/BOT_API.md),
«Привязка VK»):

- Шаг выполнен, когда VK привязан, сообщения сообщества разрешены и у бота есть рабочий
  токен. Если VK не ответил на проверку токена, шаг тоже выполнен.
- Если позже человек запретит сообщения или токен перестанет работать, шаг снова не
  выполнен. Ожидающую заявку тогда не одобрить, а действующий аккаунт после срока закрыт до
  исправления.
- Срок для одобренных аккаунтов задаёт `BOT_LINK_DEADLINE` при выкладке, дату выбирает
  владелец. Без неё — только баннер.
- Аккаунт, созданный входом через VK ID, привязывается только к тому же VK.

Как этап 4 понимает рассылки (подробно — [BOT_API.md](../../backend/docs/BOT_API.md), «Рассылки»):

- В VK рассылку получают одобренные действующие аккаунты, у которых бот подключён на момент
  отправки. Список не меняется: кто привяжет VK позже, эту рассылку не получит.
- Уведомление на сайте получают все действующие аккаунты, кроме автора, и с VK, и без него.
  Оно открывает страницу с полным текстом.
- Отмена останавливает ещё не отправленное. Уже отправленное остаётся отправленным, уведомления
  на сайте остаются.
- Автор видит ход отправки счётчиками, без списка, кто что получил.

## Права

Источник истины — `POLICY` в [access.py](../../backend/access.py).

| Действие | Capability | Кто |
| --- | --- | --- |
| `bot.console.view` | `view_bot_console` | мастер блока IT, сопровождающие бота |
| `bot.console.operate` (этап 5) | `operate_bot` | мастер блока IT, сопровождающие бота |
| `bot.maintainers.manage` | `manage_bot_maintainers` | мастер блока IT |
| `broadcast.send` (этап 4) | `send_broadcast` | председатель, замы, отправители рассылок |
| `broadcast.senders.manage` | `manage_broadcast_senders` | председатель, замы |

Назначения хранятся строками `role_assignments` с `scope_kind = "site"` и ролями
`bot_maintainer` и `broadcaster`.

## Внешние действия

Разрешения владельца от 4 ноября:

- запускать бота локально с его `.env`, в котором прописаны тестовые сообщества; проверки
  в интерфейсе просить у владельца;
- выпускать новую версию бота — после всех проверок и тестов;
- выкладка сайта и настройка сервера — не в этой работе: для них готовится промпт другому
  агенту;
- настройки сообществ ВК делает владелец по запросу.

К реальному сайту и серверу не подключаться и ничего там не смотреть.

## Этапы

| Этап | Содержание |
| --- | --- |
| 0 | Контракт `/api/bot/v1`, эта запись, запись 0009 в документации бота |
| 1 | Основа: служебный доступ, цикл опроса, статус и ошибки бота, права и назначения |
| 2 | Привязка аккаунта к VK и обязательный шаг регистрации |
| 3 | Уведомления через очередь `notification_delivery_events` |
| 4 | Рассылки |
| 5 | Консоль: интерфейс, перезапуск, журнал, обновление и откат |
| 6 | Сквозная проверка, замеры, документация, репетиция миграции |

Этап 2 проверен вживую 4 ноября: локальный сайт и бот с тестовым сообществом. Привязка по
команде `привязать КОД`, выдача токена, отказ привязать тот же VK второму аккаунту, одобрение
привязанной заявки и закрытие сайта после срока сработали. Не проверены вживую, только тестами:
события запрета и разрешения сообщений (владелец — создатель тестового сообщества и не может
запретить себе сообщения) и передача кода через `ref` по кнопке «Начать» (у владельца уже был
диалог с ботом). Их стоит проверить с другого аккаунта VK до выкладки.

Этап 3 проверен вживую 5 ноября на том же стенде. Владелец привязал VK к аккаунту исполнителя
задачи, автор задачи сменил её статус. Через 3 секунды уведомление «Изменён статус задачи» со
ссылкой на задачу пришло в ЛС бота с первой попытки, без карточки ссылки. Ссылка стенда вела на
`http://`, браузер открыл её только после ручной правки протокола. В боевом окружении с
интеграцией сайт требует адрес `https://`. Не проверены вживую, только тестами: запрет сообщений
при отправке, повторы после ошибок VK и истечение очереди через сутки.

Этап 4 проверен вживую 5 ноября на свежем стенде. Владелец привязал VK к аккаунту участника,
председатель отправил рассылку из раздела «Рассылки» после подсказки «Получат в VK: 1 из …» и
подтверждения. Бот отправил пачку из одного получателя через секунду после отправки, с первой
попытки: текст пришёл как написан, с переносами строк и без карточки ссылки. Пачка закрылась
отправленной, счётчик бота `broadcasts_sent` вырос до 1. Уведомление о рассылке получили на
сайте 18 аккаунтов, все, кроме автора. Колокольчик открыл страницу с полным текстом, история
показала «Отправлена» и «Отправлено 1 из 1». Не проверены вживую, только тестами: отмена до
отправки, запрет сообщений при рассылке, повторы пачки после ошибок VK и истечение через сутки.
